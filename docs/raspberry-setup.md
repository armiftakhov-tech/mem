# Raspberry Pi: подготовка сервера с нуля

Цель: Raspberry Pi 4 (8 ГБ) с Raspberry Pi OS Lite 64-bit, загрузкой с SSD, SSH по ключу, постоянным адресом в домашней сети, обновлениями, синхронизацией времени и Docker + Compose.

Охват: этапы 0–1 из `AGENTS.md`. Приложение работает только в домашней сети по HTTPS.
**Не входит:** WireGuard, nftables, резервные копии. Это отдельные этапы, потом.

Время: 1–2 часа, если всё железо на месте.

---

## Шаг 0. Проверить провайдера (можно сделать прямо сейчас)

От этого зависит, будет ли вообще удалённый доступ через WireGuard. Малинка для проверки не нужна.

1. Зайти в админку роутера (обычно `192.168.0.1` или `192.168.1.1`, адрес и пароль на наклейке снизу).
2. Найти **WAN IP** / «Внешний IP» / «IP-адрес интернета».
3. С телефона **через домашний Wi-Fi** открыть https://ifconfig.me.
4. Сравнить:

| Что видишь | Что значит |
|---|---|
| WAN IP роутера = IP на ifconfig.me | Белый IP. Хорошо. |
| WAN IP начинается на `100.64.`–`100.127.`, `10.`, `172.16.`–`172.31.`, `192.168.` | **CGNAT.** Без внешнего посредника удалённого доступа не будет. |
| Адреса разные по другой причине | Скорее всего тоже CGNAT или двойной NAT. Звонить провайдеру. |

5. Позвонить провайдеру и спросить ровно это: **«Нужен статический белый (публичный) IPv4-адрес. Сколько стоит и как подключить?»** Обычно это платная услуга на пару сотен рублей в месяц. Белый, но динамический IP не подходит: DDNS в `AGENTS.md` запрещён.

**Риск:** если провайдер статический белый IP не даёт, архитектура удалённого доступа из `AGENTS.md` не работает. Это надо знать до того, как писать VPN-часть.

## Шаг 1. Железо: что должно быть на столе

| # | Что | Зачем | Если нет |
|---|---|---|---|
| 1 | Raspberry Pi 4 Model B 8 ГБ | Сервер | — |

| 6 | Сетевой кабель Ethernet | Пи подключается к роутеру проводом, не по Wi-Fi | Любой патч-корд нужной длины. |

| 9 | Отдельный USB-диск для бэкапов | Понадобится позже | Пока не нужен. |

Монитор и клавиатура **не нужны**: всё делается по сети (headless). Кабель micro-HDMI пригодится только для отладки, если что-то пойдёт не так.

SSD подключать в **синий** порт USB 3.0.

## Шаг 2. Записать ОС на SSD

На компьютере:

1. Сначала создать SSH-ключ (если ещё нет). В терминале (на Windows — PowerShell):
   ```
   ssh-keygen -t ed25519
   ```
   На все вопросы — Enter (или задать пароль ключа). Публичный ключ лежит в `~/.ssh/id_ed25519.pub`.
2. Скачать и установить **Raspberry Pi Imager**: https://www.raspberrypi.com/software/
3. Подключить SSD через адаптер **к компьютеру**.
4. В Imager:
   - **Устройство:** Raspberry Pi 4.
   - **ОС:** Raspberry Pi OS (other) → **Raspberry Pi OS Lite (64-bit)**.
   - **Накопитель:** SSD. Проверь дважды, что не выбран диск компьютера.
5. Нажать «Далее» → **«Изменить настройки»** (OS customisation) и заполнить:
   - Hostname: `discipline`
   - Имя пользователя и пароль: свои (не `pi`). Пароль записать.
   - Wi-Fi: **не настраивать**.
   - Часовой пояс: `Europe/Moscow` (или свой), раскладка `us`.
   - Вкладка «Службы»: **включить SSH → «Только авторизация по ключу»**, вставить содержимое `id_ed25519.pub`.
6. Записать. Дождаться проверки. Отключить SSD от компьютера.

## Шаг 3. Первый запуск с SSD

1. Пи выключена. **microSD вынута.**
2. SSD — в синий порт USB 3.0. Ethernet — в роутер. Питание — последним.
3. Подождать 2–3 минуты.
4. Проверить, загрузилась ли:
   ```
   ping discipline.local
   ```
   Если не отвечает — посмотреть в админке роутера список DHCP-клиентов, нет ли там `discipline`.

**Если не загрузилась** (адреса нет, зелёный светодиод не мигает): на старых платах загрузчик не умеет грузиться с USB. Лечится так:

1. В Imager: Устройство Pi 4 → ОС: **Misc utility images → Bootloader (Pi 4 family) → USB Boot** → накопитель: **microSD**.
2. Вставить microSD в Пи (SSD отключить), включить питание.
3. Через ~10 секунд зелёный светодиод начнёт быстро мигать непрерывно (если подключён монитор — экран станет зелёным). Готово.
4. Выключить питание, вынуть microSD, подключить SSD, включить снова.

## Шаг 4. Подключиться по SSH

```
ssh ИМЯ@discipline.local
```

Если `.local` не резолвится (бывает на Windows и Android) — использовать IP из админки роутера: `ssh ИМЯ@192.168.x.y`.

Первый раз спросит про отпечаток ключа — ответить `yes`.

Все дальнейшие команды выполняются **на Пи** через эту SSH-сессию.

## Шаг 5. Постоянный адрес в домашней сети

Пи должна всегда иметь один и тот же IP, иначе приложение и VPN будут «теряться».

**Рекомендуемый способ — резервирование на роутере** (DHCP reservation / «Привязка IP к MAC»):

1. Узнать MAC-адрес на Пи:
   ```
   ip link show eth0
   ```
   Строка `link/ether xx:xx:xx:xx:xx:xx` — это он.
2. В админке роутера: раздел DHCP → «Резервирование адресов» → привязать этот MAC к адресу, например `192.168.1.10`.
3. Перезагрузить Пи (`sudo reboot`) и проверить, что адрес стал нужным:
   ```
   hostname -I
   ```

Почему не прописывать статический IP на самой Пи: при смене роутера или подсети Пи станет недоступна, и чинить придётся с монитором и клавиатурой. Резервирование надёжнее для новичка.

Записать адрес: **IP Пи = ______________**.

## Шаг 7. Проверить, что всё работает с SSD и без проблем с питанием

```
findmnt /
```
В колонке SOURCE должно быть `/dev/sda2`. Если `/dev/mmcblk0p2` — система загрузилась с microSD, вернуться к шагу 3.

```
lsusb -t
```
У SSD должно быть `Driver=uas`. Если `usb-storage` — адаптер без UASP, будет медленнее. Работать будет, но лучше заменить адаптер.

```
vcgencmd get_throttled
```
Должно быть `throttled=0x0`. Любое другое значение — проблемы с питанием или перегрев. Менять блок питания или корпус.

```
vcgencmd measure_temp
```
В простое нормально до 60 °C.

TRIM для SSD (продлевает жизнь диска):
```
sudo fstrim -v /
```
Если выводит количество обрезанных байт — включить еженедельный запуск:
```
sudo systemctl enable --now fstrim.timer
```
Если ошибка «the discard operation is not supported» — адаптер не поддерживает TRIM. Не критично, пропустить.

## Шаг 8. Время

```
timedatectl
```

Нужно увидеть:
- `Time zone: Europe/Moscow` (или свой);
- `System clock synchronized: yes`;
- `NTP service: active`.

Если часовой пояс не тот:
```
sudo timedatectl set-timezone Europe/Moscow
```

Если синхронизации нет:
```
sudo systemctl enable --now systemd-timesyncd
```

Правильное время критично: от него зависят сроки заданий, напоминания, срок действия bootstrap-токена и HTTPS-сертификаты.

## Шаг 9. Закрыть вход по паролю в SSH

Если в шаге 2 выбрано «только по ключу», пароль уже выключен. Проверить и зафиксировать явно:

```
sudo tee /etc/ssh/sshd_config.d/10-hardening.conf > /dev/null <<'CONF'
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
CONF
sudo sshd -t && sudo systemctl reload ssh
```

**Не закрывая текущую SSH-сессию**, открыть второй терминал и проверить вход: `ssh ИМЯ@discipline.local`. Получилось — можно закрывать старую.

Важно: ключ `~/.ssh/id_ed25519` с компьютера теперь единственный способ войти. Сохранить его копию в надёжном месте (менеджер паролей). Потеряешь — придётся подключать монитор и клавиатуру.

## Шаг 10. Docker Engine и Docker Compose

Официальный репозиторий Docker:

```
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Разрешить своему пользователю работать с Docker без `sudo`:
```
sudo usermod -aG docker $USER
```
Выйти (`exit`) и зайти по SSH заново.

Ограничить логи контейнеров, чтобы они не съели SSD:
```
sudo tee /etc/docker/daemon.json > /dev/null <<'CONF'
{
  "log-driver": "local",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
CONF
sudo systemctl restart docker
```

Проверка:
```
docker run --rm hello-world
docker compose version
systemctl is-enabled docker
```
Ожидается: «Hello from Docker!», версия Compose v2, `enabled` (Docker сам стартует после перезагрузки).

## Шаг 12. Итоговая проверка

Перезагрузить (`sudo reboot`), зайти снова и пройтись по списку:

- [ ] Шаг 0: ответ провайдера получен — белый статический IP есть / нет / сколько стоит.
- [ ] `ssh ИМЯ@discipline.local` работает по ключу, по паролю — нет.
- [ ] `hostname -I` показывает зарезервированный адрес.
- [ ] `findmnt /` → `/dev/sda2`.
- [ ] `vcgencmd get_throttled` → `0x0`.
- [ ] `timedatectl` → синхронизировано, верный часовой пояс.
- [ ] `docker run --rm hello-world` работает без `sudo`.
- [ ] `docker compose version` показывает v2.
- [ ] `df -h /` — свободно больше 80 %.

Всё отмечено — сервер готов к развёртыванию приложения.

## Что дальше (не сейчас)

1. **Развёртывание приложения** (этап 1): `docker-compose.yml` с `caddy` + `app`, HTTPS с внутренним сертификатом Caddy. Корневой сертификат Caddy придётся один раз установить на телефоны родителей, иначе браузер будет ругаться.
2. **Файрвол nftables.** Отложен сознательно: Docker сам управляет правилами фильтрации, и неаккуратный `nftables`-конфиг ломает сеть контейнеров. Пока порты на роутере не проброшены, Пи снаружи недоступна.
3. **WireGuard** — только после подтверждения белого статического IP (шаг 0).
4. **Резервные копии** на отдельный USB-диск.

## Риски

- **CGNAT у провайдера** — удалённого доступа без внешнего посредника нет. Проверить в шаге 0.
- **Слабый блок питания** — порча файловой системы и базы. Только официальный 15 Вт.
- **Потеря SSH-ключа** — доступ только физически.
- **Нет файрвола на хосте** до этапа VPN. Допустимо, пока на роутере ничего не проброшено. Пробрасывать порты до появления nftables нельзя.

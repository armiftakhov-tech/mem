# 02 — Модель данных «Дисциплина»

Версия 1.1. Соответствует [`AGENTS.md`](../AGENTS.md) 1.1. При противоречии прав `AGENTS.md`.

Одна семья, несколько равноправных родителей, ребёнок без логина. Всё на одном Raspberry Pi в SQLite.

Общие правила для всех таблиц:

- `id` — UUID, генерируется на сервере;
- все моменты времени хранятся в UTC (`*_at`);
- локальные даты и время без зоны (`*_on`, `*_local_time`) интерпретируются в часовом поясе семьи;
- физически ничего критичного не удаляется: только смена статуса.

## 1. Учётная запись

`Account` — техническая учётка для входа. Это не объект «родитель».

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор учётки. |
| `email` | Логин. Уникален. Писем приложение не шлёт. |
| `password_hash` | Только Argon2id-хеш. |
| `status` | `active / blocked`. Проверяется на каждом запросе. |
| `created_at` | Когда зарегистрирована. |
| `last_login_at` | Последний вход: безопасность и диагностика. |

Восстановление пароля — локальная админская команда, не UI.

## 2. Сессия

`Session` — серверная сессия. Cookie хранит только её идентификатор.

| Атрибут | Что и зачем |
|---|---|
| `id_hash` | Хеш идентификатора из cookie. Сам идентификатор в БД не лежит. |
| `account_id` | Чья сессия. |
| `csrf_token_hash` | Для CSRF-защиты. |
| `created_at` | Когда создана. |
| `last_seen_at` | Последняя активность. |
| `expires_at` | Когда истекает. |
| `revoked_at` | Принудительный выход. |

## 3. Bootstrap-токен

`BootstrapToken` — одноразовый ключ первого запуска.

| Атрибут | Что и зачем |
|---|---|
| `token_hash` | Хеш токена. Сам токен — только в консоли администратора. |
| `expires_at` | Ограниченный срок. |
| `used_at` | Заполнено — токен мёртв, открытая регистрация закрыта. |

## 4. Семья

`Family` — контейнер данных и граница доступа.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор семьи. |
| `name` | Условное название. Необязательно. |
| `timezone` | IANA-зона (`Europe/Moscow`), не UTC-offset. По ней показываем время и считаем «сегодня». |
| `created_at` | Когда создана. |

В MVP семья одна, но проверка принадлежности к семье на backend обязательна (тест 2 в `AGENTS.md`).

## 5. Родитель

`Parent` — предметный объект родителя.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор родителя. |
| `family_id` | Семья. |
| `account_id` | Учётка. Уникален: один аккаунт — одна семья. |
| `name` | Имя для интерфейса и истории. |
| `status` | `active / removed`. |
| `created_at` | Когда добавлен. |

Ролей нет: все активные родители равноправны.

## 6. Ребёнок

`Child` — профиль ребёнка. Логина и интерфейса нет.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор ребёнка. |
| `family_id` | Семья. |
| `name` | Имя. |
| `birth_date` | Необязательное. |
| `created_at` | Когда создан. |

Статуса и архива нет. Ребёнка можно удалить физически, только пока у него нет ни одного `Assignment` и `Recurrence`: это исправление ошибки ввода. Удаление каскадом убирает его `ParentChildRelation` и пишется в `AuditEvent`. Как только появилось хоть одно задание, удалить ребёнка нельзя: история важнее.

## 7. Связь родителя и ребёнка

`ParentChildRelation` — кто кому родитель.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор связи. |
| `parent_id` | Родитель. |
| `child_id` | Ребёнок. |
| `relation_type` | `father / mother / guardian / other`. Только для отображения. |
| `status` | `active / ended`. |
| `created_at` | Когда создана. |

Инвариант: каждый активный родитель связан со всеми детьми семьи. Связи создаются автоматически при добавлении родителя или ребёнка. Уникальность `(parent_id, child_id)`.

## 8. Приглашение

`FamilyInvitation` — одноразовый код для второго родителя.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `family_id` | Куда зовём. |
| `code_hash` | Хеш кода. Полный код не логируется. |
| `created_by_parent_id` | Кто пригласил. |
| `expires_at` | Срок действия. |
| `accepted_by_account_id` | Кто принял. Повторное принятие тем же аккаунтом — no-op. |
| `accepted_at` | Когда. |
| `revoked_at` | Отозвано. |

## 9. Повтор

`Recurrence` — правило регулярного задания. Добавлено в MVP в версии 1.1.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `family_id` | Семья. |
| `child_id` | Кому. |
| `created_by_parent_id` | Кто завёл. |
| `text` | Что сделать. Копируется в каждое задание. |
| `success_criteria` | Признак выполнения. Необязательное. |
| `weekdays` | Дни недели (битовая маска пн–вс). |
| `due_local_time` | Срок выполнения в локальном времени. |
| `check_local_time` | Время проверки. `check_local_time >= due_local_time`. |
| `starts_on` | С какой даты. |
| `ends_on` | По какую. Пусто — бессрочно. |
| `status` | `active / paused / ended`. |
| `version` | Optimistic locking. |
| `created_at` / `updated_at` | Аудит. |

Как работает:

- планировщик раз в день (и после старта) создаёт `Assignment` на сегодня по зоне семьи;
- задним числом за пропущенные дни ничего не создаётся;
- уникальность `(recurrence_id, occurrence_date)` в `Assignment` гарантирует одно задание на день;
- правка или пауза правила не трогает уже созданные задания;
- отдельное сгенерированное задание можно изменить или отменить, как разовое.

## 10. Задание

`Assignment` — основной объект. Разовое или порождённое `Recurrence`.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `family_id` | Семья. Для проверки доступа без джойнов. |
| `child_id` | Кому. |
| `created_by_parent_id` | Кто дал. Для сгенерированных — автор правила. |
| `recurrence_id` | Из какого правила. Пусто — разовое. |
| `occurrence_date` | Дата повтора. Заполнено только вместе с `recurrence_id`. |
| `text` | Что сделать. |
| `success_criteria` | Признак выполнения. Необязательное. |
| `due_at` | Срок выполнения ребёнком. |
| `check_at` | Время проверки. `check_at >= due_at`. |
| `state` | `active / closed / cancelled`. Создаётся сразу `active`, черновиков нет. |
| `version` | Optimistic locking: изменение с устаревшей версией отклоняется. |
| `idempotency_key` | Клиентский ключ создания. Уникален. |
| `created_at` / `updated_at` | Аудит. |
| `closed_at` | Когда закрыто проверкой. |
| `cancelled_at` / `cancelled_by_parent_id` | Отмена. Запись не удаляется. |

`overdue` не храним: `state = active` и `now > check_at`.

Почему `child_id`, а не `relation_id`: все родители равноправны и правят любое задание, поэтому привязка к паре «родитель–ребёнок» смысла не несёт. Кто дал — `created_by_parent_id`.

## 11. Проверка

`AssignmentReview` — результат проверки. Только родитель. Отметки ребёнка в MVP нет.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `assignment_id` | Какое задание. |
| `reviewer_parent_id` | Кто проверил. |
| `outcome` | `done / partial / not_done`. |
| `is_current` | Текущий результат. Частичный уникальный индекс: одна `is_current = true` на задание. |
| `supersedes_review_id` | Какую проверку исправляет. Пусто — первая. |
| `idempotency_key` | Защита от двойного клика. Уникален. |
| `reviewed_at` | Когда. |

Правила:

- первая проверка и закрытие задания — одна транзакция;
- исправление создаёт новую запись, у старой `is_current = false`, она не перезаписывается;
- два одновременных результата: второй получает конфликт, а не вторую текущую проверку.

Комментарий сюда не кладём, он в `Comment`.

## 12. Обсуждение

`Discussion` — контейнер комментариев вокруг задания.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `assignment_id` | К какому заданию. Уникален: одно обсуждение на задание. |
| `created_at` | Когда создано (лениво, при первом комментарии). |

## 13. Комментарий

`Comment` — заметка родителя. Например: «Не выполнила, потому что не поняла условие» или «Задание сформулировал расплывчато».

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `discussion_id` | Обсуждение. |
| `author_parent_id` | Автор. Только родитель. |
| `text` | Содержание. |
| `created_at` | Когда. |
| `edited_at` | Когда изменён. |
| `deleted_at` | Мягкое удаление. |

## 14. Напоминание

`Reminder` — план «когда напомнить». Хранится в БД, не в памяти процесса.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `assignment_id` | О каком задании. |
| `kind` | `check_due` (пора проверить). Других в MVP нет. |
| `scheduled_at` | Когда сработать. |
| `status` | `scheduled / processed / cancelled`. |
| `processed_at` | Когда обработано. |
| `created_at` | Когда создано. |

- изменение `check_at` отменяет будущие напоминания задания и создаёт новые;
- закрытие или отмена задания отменяет его напоминания;
- после перезапуска просроченные `scheduled` обрабатываются один раз.

## 15. Уведомление

`Notification` — внутреннее уведомление родителю в приложении. Внешних каналов нет, поэтому `NotificationDelivery` не нужен.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `parent_id` | Кому. |
| `type` | `reminder / assignment_changed / review_added`. |
| `assignment_id` | О чём. |
| `reminder_id` | Источник, если это напоминание. |
| `dedup_key` | Ключ дедупликации, уникальность `(parent_id, dedup_key)`. Для напоминания — `reminder:<reminder_id>`, для остальных — `<type>:<audit_event_id>`. Повторная обработка события не создаёт второе уведомление. |
| `created_at` | Когда создано. |
| `read_at` | Когда прочитано. Пусто — входит в счётчик непрочитанных. |

## 16. Настройки уведомлений

`NotificationSettings` — у каждого родителя свои.

| Атрибут | Что и зачем |
|---|---|
| `parent_id` | Чьи. Первичный ключ. |
| `reminders_enabled` | Получать напоминания о проверке. |
| `changes_enabled` | Получать уведомления об изменениях другого родителя. |
| `browser_notifications_enabled` | Показывать локальное уведомление браузера, если он разрешил. |
| `updated_at` | Когда менялись. |

## 17. Событие аудита

`AuditEvent` — неизменяемая запись о действии. Из неё строится история.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `family_id` | Семья. Пусто для системных событий. |
| `actor_account_id` | Кто. Пусто — система (планировщик). |
| `entity_type` | `assignment / review / recurrence / invitation / account / …`. |
| `entity_id` | Какой объект. |
| `event_type` | `created / changed / cancelled / reviewed / review_corrected / login_ok / login_failed / …`. |
| `payload` | JSON: что изменилось. Без паролей, токенов и cookie. |
| `occurred_at` | Когда. |

Записывается в той же транзакции, что и само действие. Входы журналируются здесь, а лимит попыток считается по `LoginAttempt`.

## 18. Обработанная команда

`ProcessedCommand` — общая защита от повторов для команд без собственного уникального ключа (изменение и отмена задания, принятие приглашения). Создание задания, проверка и исправление защищены своим `idempotency_key`.

| Атрибут | Что и зачем |
|---|---|
| `idempotency_key` | Клиентский `command_id`. Первичный ключ вместе с `account_id`. |
| `account_id` | Кто прислал. |
| `command` | Тип команды. |
| `response` | Сохранённый ответ: повтор получает тот же результат. |
| `created_at` | Когда. Старые записи можно чистить. |

## 19. Попытка входа

`LoginAttempt` — основа для лимита попыток входа (`AGENTS.md` §10). `AuditEvent` для этого не подходит: при неизвестном email там нет актора.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор. |
| `email_normalized` | Введённый логин в нижнем регистре. Пишется, даже если такой учётки нет. |
| `account_id` | Учётка, если email найден. |
| `ip` | Адрес клиента: домашняя сеть или WireGuard-пир. |
| `success` | Удачно или нет. |
| `attempted_at` | Когда. |

Лимит считается по неуспешным попыткам за окно времени отдельно для email и для IP. Пароль не пишется никогда. Старые записи можно чистить.

## 20. Права

Проверяются только на backend, внутри транзакции команды.

| Кто | Что может |
|---|---|
| Аноним | Вход. Регистрация только по действующему `BootstrapToken` или `FamilyInvitation`. |
| Активный родитель | Всё внутри своей семьи: дети, задания, повторы, проверки и их исправления, комментарии, приглашения. Ролей и выборочных прав на детей нет. |
| Активный родитель | Свои `NotificationSettings`, свои уведомления, свои сессии. Чужие не может. |
| Родитель со статусом `removed` или заблокированная учётка | Ничего. Сессии отзываются. |
| Администратор Pi | Вне приложения: CLI для сброса пароля и выпуска bootstrap-токена. Продуктовых прав не получает. |
| Кто угодно | Ничего за пределами своей семьи. Объект чужой семьи отдаётся как `404`, а не `403`. |

Ограничения: комментарий правит и удаляет только его автор. Аудит и проверки неизменяемы для всех.

## Итоговая логика

```
Account ── Session
   │
Parent ──┬── ParentChildRelation ──┐
   │     │                         │
Family ──┴──────────── Child ◀─────┘
                         │
          Recurrence ──▶ Assignment ──┬── AssignmentReview (история исправлений)
                                      ├── Discussion ── Comment
                                      └── Reminder ── Notification ── Parent

AuditEvent — по всем изменяющим действиям
LoginAttempt — по всем попыткам входа
```

## Не входит в MVP

| Что | Почему |
|---|---|
| Отметка ребёнка «сделано» / `author_type` в проверке | `AGENTS.md` §28: у ребёнка нет интерфейса. |
| `ParentNote` (личный пример родителя) | Не в MVP. Вернуть отдельным решением, когда основной цикл заработает. |
| `NotificationDelivery` | Внешних каналов нет, доставлять некуда. |
| `AccountSettings` | Часовой пояс у семьи, уведомления в `NotificationSettings`. |
| Статус `draft` у задания | Черновиков в MVP нет. |
| Баллы, серии, награды, вложения | `AGENTS.md` §28. |

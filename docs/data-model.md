# Модель данных трекера заданий

Версия 1. Личный инструмент для одной семьи: два родителя (у каждого свой логин), двое детей (10 и ~12 лет). Не SaaS.

Цель первого этапа: дисциплина и форма через задания, последовательный контроль, обратную связь и личный пример.

## 1. Родитель

`Parent` — взрослый с доступом в приложение. Учётка и предметный объект совмещены: семья одна, разделять незачем.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор родителя. |
| `name` | Имя для интерфейса и истории («кто дал», «кто проверил»). |
| `email` | Логин. Пароли и сессии отдаём сервису авторизации, свою не пишем. |
| `timezone` | Чтобы время проверки не съезжало. |
| `created_at` | Когда добавлен. |

## 2. Ребёнок

`Child` — профиль ребёнка. Логин не обязателен.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор ребёнка. |
| `name` | Имя. |
| `birth_date` | Возраст влияет на формулировку заданий. Необязательное. |
| `status` | `active / archived`. |
| `created_at` | Когда профиль создан. |

## 3. Шаблон повторения

`Recurrence` — правило для регулярных заданий («каждый будний день — 20 минут чтения»). Без него ежедневные задания придётся вбивать руками каждый день.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор шаблона. |
| `child_id` | Кому. |
| `author_parent_id` | Кто завёл правило. |
| `text` | Что сделать. Копируется в каждое задание. |
| `success_criteria` | Признак выполнения. Необязательное. |
| `schedule` | Дни недели или правило повтора. |
| `check_time` | Во сколько проверять. |
| `active_from` / `active_until` | Период действия. `active_until` пустое — бессрочно. |
| `status` | `active / paused / ended`. |
| `created_at` | Когда создан. |

Шаблон порождает задания, но сам заданием не является. Правка шаблона не переписывает уже выданные задания.

## 4. Задание

`Assignment` — основной объект дисциплины ребёнка. Конкретное задание на конкретный день.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор задания. |
| `child_id` | Кому дано. |
| `author_parent_id` | Кто дал. |
| `recurrence_id` | Из какого шаблона создано. Пусто — разовое. |
| `text` | Что именно требуется сделать. |
| `success_criteria` | По какому признаку понятно, что выполнено. Необязательное. |
| `planned_for` | В какой день выполнить. |
| `check_at` | Когда родителю проверить. |
| `state` | `draft / active / closed / cancelled`. |
| `created_at` | Когда запись появилась. |
| `updated_at` | Последнее изменение. |
| `closed_at` | Когда закрыли. |

`overdue` не храним: вычисляется из `check_at` и `state`.

## 5. Проверка

`Review` — итог проверки задания плюс комментарий. Комментарии отдельным объектом не выделяем: в версии 1 обсуждение = проверка с текстом.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор проверки. |
| `assignment_id` | Какое задание. |
| `author_type` | `parent / child`. Ребёнок тоже может оставить отметку: «сделал», «не понял условие». |
| `author_id` | Кто именно. |
| `outcome` | `done / partial / not_done`. Обязательно для родителя, необязательно для ребёнка. |
| `comment` | Текст: причина, замечание, похвала. Необязательное. |
| `created_at` | Когда. |

Итог задания — последняя проверка родителя. Отметка ребёнка — самооценка, а не вердикт. Расхождение между ними — полезный сигнал.

## 6. Заметка родителя

`ParentNote` — личный пример и самопроверка родителя. Дисциплина без примера не работает, поэтому родитель трекает и себя.

| Атрибут | Что и зачем |
|---|---|
| `id` | Идентификатор заметки. |
| `parent_id` | Чья. |
| `date` | За какой день. |
| `kind` | `commitment / self_check / observation` — обязательство, самопроверка, наблюдение. |
| `text` | Содержание: «проверил вовремя», «сорвался, накричал», «задание сформулировал расплывчато». |
| `assignment_id` | Связанное задание. Необязательное. |
| `created_at` | Когда. |

## Итоговая логика

```
Parent ──дал──▶ Assignment ◀──кому── Child
                   ▲  │
       Recurrence ─┘  └──▶ Review (parent | child)

Parent ──▶ ParentNote
```

## Отложено до продукта

Нужно, если инструмент станет продуктом для многих семей. Сейчас — лишний вес.

| Объект | Почему отложен |
|---|---|
| `Account` отдельно от `Parent` | Одна семья, разделение не даёт ничего. |
| `AccountSettings` | Пара полей влезает в `Parent`. |
| `Family` | Граница доступа нужна, когда семей больше одной. |
| `ParentChildRelation` | Оба родителя работают со всеми детьми. Тип связи не влияет на логику. |
| `Discussion` + `Comment` | Покрывается полем `comment` в `Review`. |
| `Reminder` | Хватит `check_at` и одного способа напоминания. |
| `NotificationDelivery` | Диагностика доставки нужна при масштабе. |
| `DomainEvent` | История пока = `created_at`/`updated_at` + список проверок. |
